- [ ] **FAIL:** The project **does not** meet the "bit-for-bit identical" and "high-performance" requirements. While the performance is excellent, the core correctness claim is invalid due to significant failures in accuracy and completeness.

## Issues Found (if any)
1.  **Critical Failure: Adversarial Tests Fail:** The Python port is not "bit-for-bit identical" to the C++ reference. While it passes for the simple `001-1_fingering.txt` test case, it fails on all three new, more complex adversarial test cases (`022-1`, `002-1`, `126-2`). This indicates a significant, data-dependent bug in the core logic that was not caught by the original test suite.
2.  **Critical Failure: Incomplete Implementation (Missing Order-3 HMM):** The `viterbi_3rd_order_numba` function is entirely missing from the codebase. The parameter loader can parse Order-3 files, but the core algorithm to use them does not exist. This makes the Order-3 functionality unusable and the project incomplete.
3.  **Critical Failure: Stale/Incorrect Reference Data:** The original `ref_110.txt` file committed by the developer is different from the one generated by the current C++ source code. This proves that the original test suite was, at least in part, running against outdated or incorrect "ground truth" data, invalidating those test results.
4.  **Minor Failure: Evaluation Test Fails:** The baseline test suite fails on `test_evaluation.py` due to a small discrepancy in the calculated "General" metric (`0.001066` vs a tolerance of `0.001`). This is a minor issue compared to the critical failures above.

## Suggestions for Improvement (Optional)
- The core Viterbi and/or `TimeDepPitchOrder` logic needs to be debugged to understand why it fails on complex, unseen data.
- The `viterbi_3rd_order_numba` function must be implemented to complete the project requirements.
- The test suite must be expanded to include a wider variety of score files to ensure robustness.
