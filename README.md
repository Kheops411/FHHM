# High-Performance Python Port of Piano Fingering HMM

This project is a high-performance Python port of a C++ Hidden Markov Model (HMM) for piano fingering estimation. The primary goal was to create a Python implementation that is "bit-for-bit identical" to the original C++ code, ensuring that for any given input, the output is exactly the same. This was achieved through a rigorous, test-driven development process that involved comparing the Python output against ground truth data generated by the C++ application at every step.

The project was developed in several phases, each of which is now complete and verified by a comprehensive test suite.

## Project Structure

The project is organized into the following directories:

-   `cpp/`: Contains the original C++ implementation, including source code, compiled binaries, and test probes.
-   `python/`: Contains the new Python port, organized as a Python package.
    -   `python/tests/`: Contains the pytest suite for the Python port.
        -   `python/tests/ref_outputs/`: Contains the ground truth data files generated by the C++ probes.
-   `scores/`: Contains the PIG (Piano Input Format from Ground Truth) score files used for testing and training.

## Files Created

### Python Source (`python/`)

-   `utils.py`: A core module containing utility functions for data parsing, processing, and HMM-related calculations.
    -   **Lattice Logic:** `pitch_to_keypos`, `subtract_keypos`, `lattice_delta_to_index`. These functions implement the keyboard lattice system, which is a core component of the HMM's emission probability calculation. They were implemented using a pre-computed Look-Up Table (LUT) for performance and are optimized with Numba.
    -   **Data Parsing:** `load_pig_file`, `sitch_to_pitch`, `clean_finger_str`. This set of functions provides a robust parser for the whitespace-agnostic PIG score file format. It correctly handles comments, converts string pitches (e.g., "C#4") to MIDI values, and parses complex finger notations (e.g., "4_1") into integers.
    -   **Data Ordering:** `apply_time_dep_pitch_order`. This function replicates the C++ `TimeDepPitchOrder` logic, which clusters notes that occur close in time and sorts them by pitch. This is a critical step for ensuring the Viterbi algorithm receives the notes in the correct order.
-   `model.py`: This module contains the core HMM logic.
    -   `HMMParameters`: A class that loads and manages the HMM parameters from the `.txt` files. It automatically detects the HMM order (2 or 3) and correctly handles the complex interpolation and normalization logic from the C++ `ReadParamFile` function.
    -   `viterbi_2nd_order_numba`: A Numba-optimized implementation of the Viterbi algorithm for the 2nd-order HMM. It is a direct, bit-for-bit identical port of the C++ `FingeringHMM_2nd::Viterbi` function.
-   `training.py`: A module for training new HMM models.
    -   `HMMTrainer`: A class that replicates the `SupervisedLearning` logic from the C++ code. It reads a set of score files, counts the occurrences of initial states, transitions, and emissions, and saves the resulting probability matrices to a file in the same format as the C++ originals.
-   `evaluate.py`: A module for evaluating the performance of a trained HMM.
    -   `multi_gt_error`, `calculate_metrics`: These functions replicate the logic of the C++ `Evaluate_MultipleGroundTruth` binary, providing a set of metrics for comparing an estimated fingering against one or more ground truth fingerings.

### Python Tests (`python/tests/`)

-   `test_lattice.py`: Verifies the correctness of the keyboard lattice logic.
-   `test_params.py`: Verifies the `HMMParameters` class.
-   `test_parsing.py`: Verifies the PIG file parser and note ordering logic.
-   `test_phase_4a.py`: Verifies the handling of finger substitutions and Order-3 HMM models.
-   `test_viterbi.py`: An end-to-end integration test that verifies the final output of the Python Viterbi algorithm against the C++ reference.
-   `test_training.py`: Verifies the output of the Python `HMMTrainer`.
-   `test_evaluation.py`: Verifies the output of the Python evaluation module.

### C++ Probes (`cpp/probes/`)

A series of small C++ programs were created to generate "ground truth" data from the original C++ implementation. These were essential for the test-driven development process.

-   `keypos_ref.cpp`, `subtr_ref.cpp`: Dumped the output of the core lattice functions.
-   `param_dump.cpp`: Dumped specific values from the HMM parameter files.
-   `score_dump.cpp`: Dumped the note order after applying the `TimeDepPitchOrder` logic.
-   `dump_parsed_fingers.cpp`: Dumped the integer representation of parsed finger strings.
-   `dump_param3_stats.cpp`: Dumped statistics from the Order-3 HMM parameter file.
-   `debug_viterbi.cpp`: A modified version of the Viterbi implementation used for debugging.

## Pitfalls and Challenges

This project was a masterclass in the challenges of creating a "bit-for-bit identical" port. The following were the most significant pitfalls encountered:

1.  **The "Trap" of Data Ordering:** The `Instructions.md` file correctly identified the `TimeDepPitchOrder` logic as a "trap." My initial Python implementation of this logic was incorrect, causing the Viterbi algorithm to fail in subtle ways. This was only resolved by creating a C++ probe to dump the exact note order and comparing it to the Python output. The final bug was a subtle difference in the clustering logic (comparing to the *previous* note vs. the *first* note in the cluster).

2.  **The Nuances of C++ File Parsing:** The C++ `>>` operator's whitespace-agnostic behavior was surprisingly difficult to replicate in Python. My initial line-by-line parsing was incorrect. The final solution, provided by the user, was a "Token Stream" approach that reads the entire file, strips comments, and then splits the content into a single stream of tokens. A further subtle bug was an overly greedy regex for stripping comments that was also removing sharps (`#`) from pitch names.

3.  **Hidden Logic in C++:** The C++ `ReadParamFile` function contained hidden logic that was not immediately apparent from the code's structure. This included:
    -   **Implicit Normalization:** The C++ code appeared to be re-normalizing the probabilities after reading them, but it was not. My initial attempts to replicate this caused the tests to fail. The final solution was to read the raw values and convert them directly to log-space.
    -   **Parameter Interpolation:** The 2nd and 3rd-order HMMs use a linear interpolation (smoothing) step that was not obvious at first glance. This was only discovered by carefully reading the C++ code and the user's hints.

4.  **Incorrect Reference Data:** The most significant blocker was the fact that the original C++ reference output was generated incorrectly. The C++ binary was failing to load the parameter file and was producing random, nonsensical output. This led me down a long and frustrating debugging path, as I was trying to make my correct Python code match a broken reference. This was only resolved when the user pointed out that the C++ output looked suspicious.

5.  **Numba `TypingError`s:** The use of Numba for performance introduced a series of `TypingError`s that were often difficult to debug. These included:
    -   Passing a Python class to a jitted function.
    -   Using an unsupported `print` statement.
    -   Unpacking a NumPy array into a tuple.
    -   Having multiple return paths with different data types.

## Conclusion

This project was a challenging but rewarding exercise in high-fidelity code porting. The final Python implementation is a robust, performant, and, most importantly, correct replication of the original C++ application. The comprehensive test suite and the detailed documentation in this `README.md` should make it easy for future developers to maintain and extend this project.
